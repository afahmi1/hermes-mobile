# Build 44: Thermocline theme pass and notification hardening

Builds on Zayd's builds 39–43: multi-reply, colored bot icons, notifications and reply actions,
the model that answered, each bot's fallback chain, and a per-build changelog. Adds the Thermocline
pass and hardens the notification hand-off. The changelog marks the current list seen on presentation
and remembers its contents, so it opens again only for a newer or changed list.

## Thermocline theme

- **Bot icons**: solid discs in each bot's stable series color (the hash cuts the bot id into
  seven arcs, one per Thermocline accent), initials in the measured ink. Dark mode gives the
  disc a faint halo in its own color, never the initials.
- **Thinking orb**: Zayd's Color orb uses Classic's rotating gradient, drifting highlight and
  colors in both themes. Reduce Motion still freezes it.
- **Dark-mode blues follow Light**: Crown fills with Light's deep `#186377` and Wing with
  `#02516A`; on-fill text is the light ink. Text, links, icons and toggles use the same hue
  lifted (`#5FA4B9` Crown, `#6EAFCB` Wing) so they stay readable on the black canvas.
- **Deep-sea glow (dark only)**: two distant bioluminescent blooms in the chosen accent color
  breathe at ~10% opacity near the canvas edges, and bubbles, buttons, cards and avatars get a
  soft 0.10 halo. No glow on text; the canvas center stays pure black. Held still under Reduce
  Motion and Reduce Transparency.

Classic and Light are pixel-stable (mean abs diff < 0.1 in unchanged regions).

## Notifications (build 41 baseline, hardened)

- Presence hand-off carries a `following` flag again: while the app holds background time the
  bridge waits out the grace window; when background time ends it pushes immediately.
- Confirmed-presence caching and single in-flight presence reports (no stale-away flapping).
- JWT refresh and rejection handling, mock-APNs host override for tests, and 410/400 device
  cleanup in the bridge pusher.
- Reply category attached to chat pushes; delivered notifications clear by collapse id or
  matching userInfo; text replies queue only after the destination opens.
